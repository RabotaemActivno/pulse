# Сущность Monitor

Pulse — сервис мониторинга доступности (uptime/health-check). Каждый `Monitor`
описывает одну отслеживаемую цель (URL): что и как часто опрашивать, что считать
успехом, а также хранит состояние выполнения проверок.

Источники: `internal/domain/monitor.go`, миграция
`migration/postgres/20260519170449_monitors.up.sql`.

## Поля и кто ими управляет

| Поле | Тип (Go / SQL) | Назначение | Кем управляется |
|------|----------------|-----------|-----------------|
| `ID` | `uuid.UUID` / `UUID PK` | Уникальный идентификатор монитора | **Система** — генерируется при создании |
| `UserID` | `uuid.UUID` / `UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE` | Владелец монитора. При удалении пользователя его мониторы каскадно удаляются | **Система** — берётся из аутентификации, не от клиента |
| `Name` | `string` / `TEXT NOT NULL` | Человекочитаемое имя монитора (для UI/списков) | **Пользователь** |
| `URL` | `string` / `TEXT NOT NULL` | Адрес, который опрашивается на доступность | **Пользователь** |
| `Method` | `string` / `TEXT NOT NULL DEFAULT 'GET'` | HTTP-метод запроса проверки | **Пользователь**, по умолчанию `GET` |
| `IntervalSeconds` | `int` / `INT NOT NULL` | Период между проверками (как часто пинговать) | **Пользователь** |
| `TimeoutSeconds` | `int` / `INT NOT NULL` | Таймаут ожидания ответа; превышение = неудачная проверка | **Пользователь** (в текущем `CreateMonitorInput` пока отсутствует) |
| `ExpectedStatus` | `int` / `INT NOT NULL DEFAULT 200` | Ожидаемый HTTP-статус; иначе проверка считается провальной | **Пользователь**, по умолчанию `200` |
| `IsActive` | `bool` / `BOOLEAN NOT NULL DEFAULT TRUE` | Включён ли мониторинг; можно паузить без удаления | **Пользователь** (toggle), по умолчанию `true` |
| `NextCheckAt` | `time.Time` / `TIMESTAMPTZ NOT NULL DEFAULT now()` | Момент следующей запланированной проверки; по нему планировщик выбирает мониторы | **Система** (воркер/scheduler) — пересчитывается после каждой проверки |
| `ConsecutiveFailures` | `int` / `INT NOT NULL DEFAULT 0` | Счётчик подряд идущих неудач; нужен для алертов/смены статуса после N сбоев | **Система** — инкремент при провале, сброс при успехе |
| `CreatedAt` | `time.Time` / `TIMESTAMPTZ DEFAULT now()` | Время создания | **Система (БД)** |
| `UpdatedAt` | `time.Time` / `TIMESTAMPTZ DEFAULT now()` | Время последнего изменения | **Система (БД/код)** |

## Группировка по смыслу

- **Идентификация и владение:** `ID`, `UserID` — задаются системой.
- **Конфигурация проверки (управляет пользователь):** `Name`, `URL`, `Method`,
  `IntervalSeconds`, `TimeoutSeconds`, `ExpectedStatus`, `IsActive`. Это то, что
  задаёт юзер при создании/редактировании.
- **Состояние выполнения (управляет фоновый воркер):** `NextCheckAt`,
  `ConsecutiveFailures`. Меняются автоматически по ходу опросов и не должны
  приходить от клиента.
- **Аудит/метаданные (БД):** `CreatedAt`, `UpdatedAt`.

## Замечания по текущему коду

- `CreateMonitorInput` сейчас принимает только `UserID`, `Name`, `URL`, `Method`,
  `IntervalSeconds`. При создании пока **не задаются** `TimeoutSeconds` и
  `ExpectedStatus`.
- `TimeoutSeconds` в SQL объявлен как `NOT NULL` **без** `DEFAULT`, поэтому INSERT
  без этого поля упадёт — нужно либо добавить его в input, либо задать дефолт в
  миграции/usecase.
- `CreateMonitor` (usecase и HTTP-handler) пока пустые заглушки — логика
  заполнения системных полей (`ID`, `NextCheckAt`, `IsActive` и т.д.) ещё не
  написана.
